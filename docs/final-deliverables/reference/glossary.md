# SAMS Glossary

| Term | Meaning in this project |
|---|---|
| Administrator (Admin) | Authorized role responsible for master data, user/access management and administrative reporting, as defined by the SRS. |
| API | Application Programming Interface; the documented interface through which clients send requests to the SAMS backend. |
| Attendance percentage | Attended counted classes divided by total counted classes, multiplied by 100, according to the project's agreed calculation policy. |
| Attendance record | A student's attendance status for a course/session/date. |
| Attendance session | A specific class meeting for which attendance is recorded. |
| Audit log | A record of sensitive actions, including actor, timestamp, action, target and outcome. |
| Course | An academic subject/course whose attendance is tracked. |
| Faculty | Instructor authorized by the system to create sessions, record/correct attendance and view assigned-course information. |
| Functional Requirement (FR) | A statement of a function the system shall provide; in the SRS identified as SAMS-F-###. |
| Non-Functional Requirement (NFR) | A measurable quality constraint such as performance, reliability, usability or recovery; identified as SAMS-NF-###. |
| RBAC | Role-Based Access Control; permissions are granted according to a user's role. |
| REST | A resource-oriented API style using HTTP methods such as GET and POST. |
| RTM | Requirements Traceability Matrix; links each requirement to a design/module, test case and status. |
| Section | A grouping of students within an academic course/term. |
| Student | Learner enrolled in a course/section who should view only their own attendance information. |
| UAT | User Acceptance Testing; representative users validate agreed workflows against acceptance criteria. |
| SRS | Software Requirements Specification; the baseline statement of system requirements. |
| TC | Test Case identifier, such as TC-AUTH-01, used by the SRS to reference verification tests. |
| TLS | Transport Layer Security, used to protect network communications. |
| CSV | Comma-Separated Values file format, often used for tabular data export. |
| PDF | Portable Document Format, used for fixed-layout documents/reports. |
| H2 | Relational database used by the README's development configuration. |
| MySQL | Relational database identified for the README's production profile. |
| HTTP 400 | Bad Request; used for invalid request/validation input as described in the repository README. |
| HTTP 404 | Not Found; used when the requested resource is missing as described in the README. |
| HTTP 409 | Conflict; used for a duplicate conflict as described in the README. |
